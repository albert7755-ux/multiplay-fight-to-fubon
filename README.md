# 富邦大樓環繞飛行（單機＋多人版）

第一人稱飛行小遊戲：從富邦大樓頂樓起飛，沿黃色虛線繞一圈降落 1F 大廳，途中穿越 5 個金環解鎖 Alphabet 4 的債券條件。

- **單機練習**：自己飛，成績上排行榜。
- **多人對戰**：輸入同一個房間代碼就進同一房（每房最多 10 人），房長按開始，全房一起倒數起飛；飛行中看得到同房對手的飛機和即時名次。
- **大螢幕總控台**：投影用，同時顯示所有房間的即時進度和總排行榜。

**排名規則**：成績＝飛行時間＋每漏掉一個金環加 5 秒，秒數越少排越前面。單機、多人算在同一張排行榜，同一個名字只留最好的一次。

> 這一包是**新的、獨立的 App**，跟原本的「飛行排位賽」可以並存，兩邊的排行榜分開算。

## 檔案有哪些

| 檔案 | 做什麼的 | 你會不會需要改 |
|---|---|---|
| `app.py` | Streamlit 外殼，負責把遊戲顯示出來 | 幾乎不用 |
| `game.html` | 遊戲本體（大樓、航線、債券條件、多人對戰、總控台） | 換債券時改這支 |
| `schema.sql` | Supabase 建表指令（成績表＋房間＋玩家位置） | 只跑一次 |
| `requirements.txt` | 要安裝的套件 | 不用 |

## 部署步驟（約 10 分鐘）

跟債速配、飛行排位賽用**同一個 Supabase 專案**就好。

### 第一段：Supabase 跑建表指令

1. 打開原本那個 Supabase 專案 → 左邊 **SQL Editor** → **New query**
2. 把 `schema.sql` **整份貼進去** → 按 **Run** → 看到 `Success`
3. 它會做三件事：
   - 在原本的 `flight_scores` 成績表多加兩個欄位（單機/多人、房間），**舊成績不受影響**
   - 新建 `flight_rooms`（房間）和 `flight_players`（房間裡的玩家）兩張表
   - 新建幾個多人對戰用的函式（進房、回報位置、開始比賽、總控台）

### 第二段：新的 GitHub repo

1. GitHub 開一個**新的** repository，例如 `flight-game-multi`
2. 把 `app.py`、`game.html`、`requirements.txt`、`schema.sql`、`README.md` 放進去

### 第三段：Streamlit 部署

1. [share.streamlit.io](https://share.streamlit.io) → **Create app** → 選新的 repo，Main file path 填 `app.py` → **Deploy**
2. **⋮ → Settings → Secrets**，貼上跟債速配**一模一樣**的兩行：

```toml
SUPABASE_URL = "https://你的專案代號.supabase.co"
SUPABASE_ANON_KEY = "eyJhbGciOi...（很長一串）"
```

3. **Save**，App 重開後就能用

## 現場怎麼玩（內訓幾十人）

1. **分組**：每組 10 人以內，每組講好一個房間代碼，例如「西湖A」「東湖B」
2. **進房**：每個人打開網址 → 填名字 → 輸入房間代碼 → 按「進入房間」
3. **開始**：第一個進房的人是房長，人到齊後按「開始比賽」，全房倒數 5 秒一起起飛
4. **大螢幕**：主持人用另一台電腦打開同一個網址，按開始畫面右下的「開啟大螢幕總控台」投影出來，所有房間的進度都在上面
5. **下一局**：大家降落後，房長按「開始下一局」就能再比一次

小提醒：
- 同一房不能有兩個人同名，請大家名字加上分行或編號
- 房長斷線 20 秒後，下一個最早進房的人自動變房長
- 倒數時才進房的人可以趕上這一局；已經起飛的就等下一局

## 平常怎麼維護

### 換成另一檔債券

打開 `game.html`，搜尋這幾個地方：

1. `var BOARD_ID="alphabet4-flight-mp";` → 換一個新的 id，排行榜才不會混在一起
2. `const INFO=[` → 五項條件（`k` 是欄位名稱、`v` 是數值，照順序對應第 1～5 個金環）
3. `20260929 本行報價` → 改成新的報價日
4. 開始畫面的 `WMBB26040004 · 飛行任務`、說明文字裡的 `Alphabet 4`、總控台的 `Alphabet 4`

改完存到 GitHub，Streamlit 會自己更新（這版的 `app.py` 沒有快取，不用 Reboot）。

### 清掉排行榜

在 Supabase 的 SQL Editor 跑：

```sql
delete from public.flight_scores where board = 'alphabet4-flight-mp';
```

房間和玩家資料不用清，超過一天沒人用的會自動清掉。

## 常見狀況

**按「進入房間」出現「找不到多人對戰的資料庫函式」**
第一段的 `schema.sql` 還沒跑，或跑到別的專案。跑完後如果還是一樣，等 1 分鐘再試（Supabase 需要一點時間認得新函式）。

**顯示「尚未設定連線」**
Streamlit 的 Secrets 沒設好，回去檢查那兩行，值要用雙引號包起來。

**對手的飛機好像慢半拍**
正常。對手的位置每秒更新一次，畫面顯示的是大約 1 秒前的位置再補成連續動作；名次和成績用伺服器時間計算，不受影響。

**電腦上按方向鍵飛機不動**
先用滑鼠點一下遊戲畫面，鍵盤才會對到遊戲。

**第一個人打開要等很久**
Streamlit Cloud 免費版太久沒人用會睡著，內訓前 5 分鐘先自己打開一次把它叫醒。

## 容量與安全性

- 多人同步走一般的資料庫讀寫（每人每秒一次），不佔 Supabase 即時連線的額度。40 人左右同時在線應該沒問題，但建議正式內訓前先找幾個同事實測一次
- 房間和玩家表：瀏覽器只能讀，寫入一律透過資料庫函式，每房最多 10 人由資料庫把關
- 成績表只開放「讀取」和「新增」，成績必須等於「飛行時間＋漏環罰秒」，亂送的數字會被擋下
- 裡面沒有任何客戶資料，只有名字和成績
- 遊戲頁面附註「僅供內部教育訓練使用，非投資建議」
